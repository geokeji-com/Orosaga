# Orosaga 在线课程 UI 与交互方案

> 文档状态：实施同步稿
> 方案版本：V2.2，对话式学习回应条实施版
> 编制日期：2026-08-03
> 最近复核：2026-08-03
> 适用范围：移山科技内部在线课程、逐节练习、学习进度和内容运营
> 参考基线：用户提供的 6 张课程界面截图、Orosaga 当前前端、GEO 基础能力测评系统

## 方案结论

在线课程采用固定左侧大纲和右侧单步学习画布。桌面端以参考图的布局比例、信息密度、步进方式和练习反馈为视觉复刻目标，品牌色、字体、权限、错误处理和数据安全接入 Orosaga 现有体系。正式开发通过截图叠加和关键区域测量校准，避免把未知设备像素比直接换算成 CSS 像素。

课程内容按小步展开。每节课由情境故事、常见误区、移山做法、底层原理、模型演示、业务例子、练习和小结组成。右侧画布一次只承担一个学习任务，学员可以随时看见自己在课程、章节、小节和当前步骤中的位置。

练习采用“作答后立即解释，解析读完后继续”的规则。答错时锁定本次选项并显示提示和完整解析，学员读完后通过学习回应条进入纠正；答对时显示完整解析，读完后进入下一节。系统记录首次选择、修改次数、误区标签和完成时间，用于后续补学推荐。

### 同类产品提供的补充经验

参考图是本项目的主要视觉依据，同类产品只用于补全学习机制。

- [Codecademy Paths](https://help.codecademy.com/hc/en-us/articles/220453248-Picking-Your-Learning-Path) 用明确里程碑组织课程、测验和项目。本方案把 20 节课分成 5 章，每章有独立成果物；前 4 章使用章末挑战，第五章由第 20 节综合实战收口。
- [Khan Academy Mastery](https://support.khanacademy.org/hc/en-us/articles/360007253831-What-is-self-paced-Mastery) 将练习结果映射到能力掌握状态，并按表现推荐补学内容。本方案将题目误区映射到具体小节，不做公开排名。
- [Coursera 的课程质量实践](https://blog.coursera.org/how-the-best-online-courses-engage-students-build-skills-and-drive-career-outcomes/) 强调选项级反馈、低压力练习和针对性回看。本方案为每个选项配置独立解释，答错后回到相关模型或业务例子。

## 方向锁定

| 设计判断 | 锁定方向                                                 |
| -------- | -------------------------------------------------------- |
| 视觉基调 | 安静、清楚、连续学习，冷白画布配单一课程蓝               |
| 内容组织 | 先交代情境和判断，再展示方法、原理、模型和练习           |
| 交互节奏 | 模型节点完整展示，作答后留在原位看解析，页面切换轻量淡入 |
| CSS 策略 | 继续使用 Orosaga 全局 CSS、命名类和现有设计令牌          |
| 设计标识 | 左侧学习轨迹与右侧大模型画布始终同时可见                 |

### 用户与使用场景

主要用户是移山科技新人、转岗员工和需要补齐 GEO 方法的项目成员。典型使用场景是工作日内的 10 至 20 分钟自学，桌面端为主，手机端用于回看、补练和查看进度。

### 视觉主张

安静、清楚、可连续学习。冷白画布承载知识，浅灰大纲承载位置，课程蓝只表达当前学习动作，绿色和红色只表达作答结果。页面保持参考图的高留白和平面边界，模型图成为每节课的视觉锚点。

### 内容主张

页面先让学员进入真实业务情境，再给出判断和模型。每一屏只处理一个问题，复杂内容拆成可前后移动的步骤，业务产出在小结页集中保存。

### 交互主张

模型节点在首发版本中保持静态，通过标题、读图提示、节点说明和模型结论完成解释；选择练习答案后，选项和解析同步出现；按钮按下使用 120 ms 的轻微缩放，页面切换使用 160 ms 的淡入和 8 px 位移。系统尊重 `prefers-reduced-motion`。

### 工程约束

- 单一 CSS 策略：继续使用项目全局 CSS 和命名类，不引入 Tailwind 或 CSS-in-JS。
- 课程令牌优先引用现有 `--ink`、`--muted`、`--paper`、`--white`、`--line`、`--blue` 和 `--green`，课程局部令牌只补充背景层级和练习状态。
- 课程内容通过服务端 API 下发，前端不打包正式测评答案。
- 所有可操作元素支持键盘、屏幕阅读器和 40 px 以上点击区域。
- 桌面验收宽度为 1920 px、1440 px 和 1280 px，移动验收宽度为 390 px、375 px 和 320 px。
- 动效只使用 `transform` 和 `opacity`，状态切换不改变文字字号。

### 内容层级

```text
课程 Course
├── 章节 Chapter，共 5 章
│   ├── 小节 Lesson，每章 4 节，共 20 节
│   │   ├── 步骤 Step，每节建议 8 至 12 步
│   │   ├── 必做练习 Practice，每节 1 题
│   │   ├── 可选迁移练习 Optional practice，增强版按需配置
│   │   └── 成果物 Artifact，每节 1 份
│   └── 前 4 章各有 1 个独立章节挑战
└── 第 20 节综合实战 Capstone，兼作第五章挑战
```

这套计数始终保持 20 节。第 20 节使用综合实战路由和评分界面，同时计入第五章完成度，不再生成第二个第五章挑战。

### 小节内的标准学习顺序

| 顺序 | 内容       | 默认呈现                         |
| ---: | ---------- | -------------------------------- |
|    1 | 背景故事   | 情境卡、对话、客户材料摘要       |
|    2 | 关键判断   | 二选一或三分支决策               |
|    3 | 常见误区   | 错误路线回放、风险标记           |
|    4 | 移山做法   | 方法步骤、交付物和检查点         |
|    5 | 底层原理   | 原理卡、术语解释、证据边界       |
|    6 | 模型演示   | 流程图、矩阵、分层图或时间线     |
|    7 | 业务例子   | 前后对照、数据片段或项目材料     |
|    8 | 练习       | 单选、排序、匹配、数据判断       |
|    9 | 详细解析   | 结论、选项解释、业务迁移和来源   |
|   10 | 小结与产出 | 本节成果物、带走清单和下一节入口 |

内容简单时可以合并相邻步骤，每节仍需保留故事、误区、移山做法、原理、模型和练习这六类内容。

## 桌面端视觉复刻规格

### 页面骨架

| 区域           | 1920 px 画布 | 1440 px 画布 | 1280 px 画布 | 规则                                         |
| -------------- | -----------: | -----------: | -----------: | -------------------------------------------- |
| 左侧大纲       |       320 px |       248 px |       248 px | 使用 `clamp(248px, 17.2vw, 320px)`，独立滚动 |
| 主画布         |     剩余宽度 |     剩余宽度 |     剩余宽度 | 背景 `course-canvas`                         |
| 正文最大宽度   |      1040 px |       920 px |       860 px | 水平居中，文本区控制在 65 至 72 ch           |
| 学习回应条     |     高 69 px |     高 69 px |     高 69 px | 固定在主画布底部                             |
| 正文顶部留白   |        80 px |        64 px |        56 px | 不设置营销式 Hero                            |
| 正文底部安全区 |        69 px |        69 px |        69 px | 回应条独立占据画布第二行                     |

6 张参考图的左栏约占整页宽度的 17%，因此栏宽按比例缩放并设置上下限。左侧与右侧使用 1 px 分隔线，侧栏和主画布保持约 4% 的亮度差。正文卡片只在练习、模型和情境材料需要明确边界时出现。

### 视觉校准方法

开发阶段为 6 个固定场景生成同尺寸截图，并与参考图做 50% 透明度叠加。每轮只校准栏宽、正文中心线、标题基线、模型外框和底栏五类几何量，再处理字体、颜色和状态细节。

| 校准项             |              允许偏差 | 验收方式                   |
| ------------------ | --------------------: | -------------------------- |
| 左栏分隔线         | 不超过视口宽度的 0.5% | 叠加图检查垂直边界         |
| 正文中心线         |           不超过 8 px | 对齐标题和模型容器中心     |
| 底栏高度与按钮基线 |           不超过 4 px | 对齐上边线、页码和按钮文字 |
| 主要容器尺寸       |          不超过 12 px | 对齐模型框和练习卡四边     |
| 状态颜色和文字     |           WCAG 2.2 AA | 自动对比度检查加人工复核   |

截图整体像素差只作为定位线索。中文字体渲染、操作系统抗锯齿和替换文案会产生合理差异，最终放行以关键几何量和交互状态为准。

### 左侧大纲

大纲从上到下包含返回课程中心、课程名称、总进度、章节组、小节组和反馈入口。每个小节作为可展开的二级目录，内部缩进显示“场景、方法、练习”三个步骤，形成章节、小节、步骤三级结构。

章节标题始终可见。当前章节和当前小节自动展开，其余层级可以折叠。小节行显示完成数量，例如 `1/3`；已完成步骤使用带勾圆点，当前步骤使用空心圆和浅蓝底，未开始步骤使用低对比圆点，受限内容显示锁和解锁条件。步骤标题分别说明业务场景、具体方法模型和本节判断，避免只显示泛化的“第几步”。

建议状态：

| 状态     | 图形       | 文字     | 背景     | 可操作性       |
| -------- | ---------- | -------- | -------- | -------------- |
| 已完成   | 绿色勾选圆 | 主文字   | 透明     | 可回看         |
| 学习中   | 蓝色进度环 | 蓝色     | 透明     | 当前展开       |
| 当前步骤 | 空心圆     | 蓝色     | 学习浅蓝 | 当前页         |
| 未开始   | 灰色圆     | 次级文字 | 透明     | 按解锁规则决定 |
| 需复习   | 琥珀提示点 | 主文字   | 琥珀浅底 | 跳到补练       |
| 未解锁   | 锁         | 禁用文字 | 透明     | 不可进入       |

大纲宽度不足时，标题按完整语义截短，保留步骤编号和状态。鼠标悬停显示完整标题，键盘聚焦也能读取完整名称。

### 右侧学习画布

画布分成标题区、内容区和补充区。标题使用 36 px 至 42 px，说明文字 17 px 至 18 px，正文 16 px，详细解析 15 px 至 16 px。中文正文行高保持 1.72 至 1.8。

内容区按步骤类型决定宽度：

- 概念阅读和解析：最大 860 px。
- 模型图和交互演示：最大 1040 px。
- 练习卡：最大 900 px。
- 数据表和对照矩阵：最大 1040 px，可横向滚动时提供可见提示。

### 学习回应条

回应条固定在主画布底部，只呈现一个全宽主动作。场景和方法使用逐节内容文案，练习根据未选择、提交、解析、纠正、完成和失败状态切换文案。回看入口位于标题元信息区，第一步显示“返回学习中心”，其余步骤显示“回看上一步”。回应条使用课程蓝、12 px 圆角和 1 px 顶部分隔线。

内容区还有超过 8 px 未读内容时，回应条先显示“继续往下看”；反馈解析未读完时显示“继续看完整解析”。每次滚动保留 48 px 上下文，抵达末尾后开放保存、提交、纠正或导航动作。

按键规则：

- `Enter` 在右侧学习屏幕内触发当前回应条动作，点击与按键使用同一业务入口。
- 单选题继续使用 Tab、方向键和 Space 的浏览器原生交互。
- 输入法组词、按键重复、组合键、文本输入、链接、按钮和打开的浮层不会触发学习主动作。
- `Escape` 收起移动端大纲或关闭帮助浮层。

浏览器前进和后退需要恢复对应步骤及滚动位置。离开有未保存成果物的步骤前显示页面内确认条，已自动保存的阅读和选择步骤直接切换。

## 视觉系统

### 色彩令牌

课程工作台复用 Orosaga 现有令牌，再增加课程局部状态。这样可以保留参考图的蓝色学习路径，也不会让课程页与公司页、工作流和测评页形成两套基础视觉语言。

```css
:root {
  --course-canvas: oklch(0.995 0.002 250);
  --course-sidebar: oklch(0.952 0.004 250);
  --course-surface: var(--white);
  --course-ink: var(--ink);
  --course-muted: var(--muted);
```

## 内容呈现组件

### 情境故事

情境页包含客户背景、当前时点、角色、已有材料和一个需要学员判断的问题。文本控制在 180 至 320 字，配合对话、邮件摘要、项目群消息、会议纪要或数据截图占位。所有虚构材料明确标记“训练情境”。

可用组件：

- `ScenarioBrief`：客户、目标、限制和时间。
- `DialogueTimeline`：按角色展开对话。
- `EvidencePacket`：展示可公开、内部参考、待确认三类材料。
- `DecisionGate`：让学员先做判断，再进入讲解。

### 常见误区与移山做法

误区页使用一条可回放的错误路线，展示当时的选择、直接后果和后续风险。移山做法页展示动作、负责人、输入、输出和完成标准。两者使用同一内容坐标，方便学员前后对照。

建议组件：

- `WrongPathReplay`：错误动作和连锁结果。
- `YishanPlaybook`：移山动作、交付物和验收点。
- `BeforeAfterCompare`：材料、过程和结果三栏对照。
- `ChecklistBuilder`：把方法变成本节成果物。

### 底层原理

原理页把研究结论、适用条件、数据边界和业务含义放在同一屏。研究结论不能写成固定平台规律，必须显示来源版本、样本条件和“可以支持的判断”。

建议组件：

- `PrincipleCard`：一句原理、适用条件和业务动作。
- `BoundaryMatrix`：已有数据、可得结论、缺失字段、补采动作。
- `EvidenceLadder`：事实、观察、相关、因果和承诺五级。
- `TermLens`：点击术语查看定义和业务例子。

### 模型图与网页模型

首发课程为 20 个小节分别配置一套 HTML 结构模型。每套模型都使用受控数据、语义化列表和 CSS 关系布局，能够随课程文案更新、适应不同屏幕、接受浏览器缩放，并在样式加载失败时保持完整阅读顺序。

### 数据和业务材料

课程中的数据表、周报、QMap、Card Pack、发布台账和归因账本使用脱敏或虚构数据。材料组件允许局部高亮、批注和前后版本切换，禁止把真实客户内部资料打包到 Web 构建产物。

- 学习注册绑定课程版本。服务端只使用完全匹配的不可变课程包解释进度；对应课程包缺失时返回 `COURSE_VERSION_UNAVAILABLE`，禁止使用当前目录代替历史目录。
- 每道四选一练习对每个答案最多保留一条作答记录，数据库约束把单次注册的记录数量限制在四条以内。
- 所有课程 API 响应发送 `Cache-Control: private, no-store`，避免受限课程内容和个人进度进入浏览器或共享代理缓存。

## 练习与反馈

### 支持的练习类型

| 类型       | 适用能力                   | 首期优先级 |
| ---------- | -------------------------- | ---------- |
| 单选题     | 唯一判断、边界识别         | P0         |
| 多选题     | 完整检查项、组合条件       | 首发完整课 |
| 排序题     | 交付流程、排查顺序         | 首发完整课 |
| 匹配题     | 指标和口径、角色和职责     | 首发完整课 |
| 分类题     | 资料权限、风险等级、信源池 | 首发完整课 |
| 数据判断题 | 分母、缺失字段、相关与因果 | P0         |
| 模型热点题 | 识别链路节点和故障位置     | P2         |
| 清单模拟   | 完成启动会、发布和复盘检查 | P2         |

第 2 节纵向切片先完成单选题，第 2、10、13、19 节试学包增加数据判断和排序。完整 20 节发布包需要支持单选、多选、排序、匹配、分类和数据判断，模型热点题与清单模拟留在增强阶段。每节首发只设置 1 道必做练习；可选迁移练习可以使用同一套题型，但不影响本节、结业、证书或测评资格。

### 作答状态机

```text
未选择
  -> 已选择
  -> 已提交
      -> 答对：显示绿色状态 + 完整解析 + 读完后进入下一节
      -> 答错：显示红色状态 + 定向提示 + 完整解析 + 进入纠正确认
          -> 读完解析并点击“重新选择”
          -> 修改选择
          -> 再次提交
              -> 答对：读完解析后进入下一节，保留首次误区记录
```

系统不自动跳转。学员阅读解析后主动点击回应条或按 Enter。答错反馈阶段锁定选项，回应条在解析末尾显示“我再想一次，重新选择”；重新选择后显示“提交我的新判断”。答对反馈阶段在解析末尾显示“解析我读完了，进入下一节”。连续两次答错后，系统提供“回看模型”入口，回到本节对应原理或业务例子。

单选题提交后禁用重复提交，服务端保存完成并返回反馈状态后再允许修改。排序、匹配和分类题使用相同的“首次作答、解析、纠正确认”结构。

### 解析卡结构

无论答对或答错，解析卡都包含：

1. 判断结果和参考答案。
2. 这道题在判断什么。
3. 当前选择为什么成立或不成立。
4. 其余选项的逐项解释。
5. 移山项目中的对应动作。
6. 关联模型、课程步骤和来源。
7. 一道迁移问题，帮助学员把结论带回新场景。

定向提示先指出应检查的证据或边界，比如“先检查现有数据有没有完整回答和回答批次”。完整解析随后给出参考答案和逐项说明。课程练习可以公开参考答案，正式测评仍按交卷后统一反馈处理。

### 正式题库的安全边界

课程覆盖正式 50 题的能力点，练习使用同能力点的新情境和新材料。课程端不复制正式题干、选项组合或答案键。正式测评内容只存放在受控题库包和服务端数据库中，员工完成交卷后由受保护的测评报告接口按权限返回题目、答案和解析；课程接口不能调用这条内容链路。

课程内容只保存稳定能力代码，例如 `DATA_BOUNDARY`、`CAUSAL_OVERREACH`，以及受控的 `GEO-001` 至 `GEO-050` 主映射。维度名称和题号关系由带版本的测评蓝图维护，课程内容不写死 `D3:DATA_BOUNDARY` 这类可能随蓝图调整的组合值。正式测评提交后，受控测评服务只向课程服务返回经过清洗的误区代码、稳定能力代码和补学代码；课程接口、前端包、日志和埋点始终不返回正式答案键、完整干扰项规则或评分密钥。

## 进度、解锁与补学

### 完成规则

- 阅读步骤打开后即可继续，系统记录有效学习时间用于课程分析，不用停留时长阻断学员。
- 交互模型需要完成该步骤声明的关键节点；使用屏幕阅读器或文字版时，以读取并确认等价内容作为完成条件。
- 必做练习需要答对，首次答案继续保留在学习记录中。
- 小节成果物完成当前节要求的最小字段并保存后，本节标记完成。
- 前 4 章各自完成 4 节后解锁章末挑战。
- 前 4 个章节挑战达到 80% 且治理关键项通过后解锁下一章，允许不限次数补练并保留首次结果。
- 第 17 至 19 节完成后解锁第 20 节综合实战。综合实战兼作第五章挑战，通过后完成第五章和整门课程。
- `RELEASE` 课程结业后开放正式测评入口。`PILOT` 课程不产生测评资格；管理员可以为已有测评记录或专项安排配置豁免。

员工完成任一符合结业规则的 `RELEASE` 版本后，后续常规内容更新不会撤回已经取得的测评资格。课程版本因安全或评分完整性问题退役时，由管理员按影响范围人工复核，再决定是否撤销证书或资格，系统不做自动批量撤销。

### 补学规则

正式测评报告已有五个维度和十类误区标签。课程中心根据报告生成补学队列：

- 指标混淆和缺失数据，优先回到测量与数据边界课程。
- 局部结论外推和因果过度，优先回到实验、平台差异和归因课程。
- 交付跳步，优先回到项目启动、诊断和闭环课程。
- 风险盲区，优先回到信源治理、内容合规和客户边界课程。

补学只改变推荐顺序，不覆盖原始学习和测评记录。

课程完成度、章节掌握度和正式测评分数分开显示。课程完成度描述流程进度，章节掌握度来自课程练习，正式测评分数继续按题库版本独立计算。

## 结业评价、课程反馈与证书

### 结业评价

结业页按固定顺序展示课程完成度、前 4 个章节挑战和第五章综合实战、五维综合分数、治理关键项、重复误区及正式测评状态。评价由服务端确定性规则生成，不使用运行时大模型自由评分，也不预测正式测评分数。

结业页的首屏只突出一个结果：课程已结业。课程成果物、详细分数、误区和来源通过下方分区展开，主操作为“参加 GEO 基础能力测评”，次操作为“查看结业证书”。`PILOT` 版本只显示试学完成摘要和反馈入口，不显示结业、证书或测评已开放。

### 课程反馈

结业后提供可跳过的反馈表，包含实用性、清晰度、难度、推荐意愿、最有帮助的小节和最多 1000 字的改进建议。反馈保存后在原位确认，不跳离结业页。页面明确说明反馈用途和查看权限，反馈结果不影响结业、证书或测评资格。

### 证书

证书页展示本人最新一张有效证书，并提供历史签发记录。已撤销证书显示状态和撤销日期，不继续提供打印操作。打印页使用 A4 横向浅纸色版式，隐藏导航、按钮和帮助入口，通过浏览器打印保存 PDF。证书固定标注“内部培训结业证明”，正式测评状态在学习中心单独显示。

证书页面和打印页面沿用登录保护、所有权校验、401 文档级跳转和浏览器历史恢复复核。首期不提供公开验证地址，也不把证书文件写入 OSS。

## 响应式方案

### 平板

在 768 px 至 1279 px 范围内，左侧大纲收进可停靠抽屉。顶部显示课程名、当前小节和大纲按钮，学习回应条保持固定。模型根据自身容器宽度选择完整图形或纵向语义结构。

### 手机

手机端只显示当前步骤。顶部 64 px 工具栏提供品牌、账户和大纲按钮；大纲从左侧抽屉展开。抽屉打开后限制学习主动作，关闭时把焦点还给大纲按钮。主画布占据剩余视口，正文内部滚动，底部使用 52 px 全宽学习回应条并叠加 `env(safe-area-inset-bottom)`。快捷键提示隐藏，连接实体键盘时 Enter 继续有效。

窄画布模型按下面规则降级：

- 模型内容容器不超过 600 px 时统一转换为纵向信息卡列表，完整保留节点文案。
- 流程、阶梯、路线图和状态机保留顺序连接线；矩阵、闭环、网络、重叠、指标树、实验和工作台移除序号与连接线。
- 非线性模型的关系含义写入模型类别和读图提示，屏幕阅读器继续按 DOM 顺序读取节点。
- 标题、节点说明和模型结论完整保留，不使用省略号截断。
- 模型容器允许课程正文内部滚动，不产生页面级横向滚动。
- 连接实体键盘时，Enter 的学习推进逻辑保持不变。

悬停样式只在支持鼠标悬停的设备启用，触摸端不会保留点击后的伪悬停状态。

## 无障碍与易用性

- 页面第一个可聚焦元素是“跳到学习内容”。
- 所有图标按钮都有可读名称，按钮和链接使用正确语义元素。
- 正确、错误、当前和锁定状态同时使用图标、文字和颜色。
- 练习结果通过 `aria-live="polite"` 播报，错误提示和解析标题建立关联。
- 模型图使用静态语义节点，节点不进入 Tab 顺序；屏幕阅读器按 DOM 顺序读取读图提示、节点和模型结论。
- 焦点样式使用 2 px 课程蓝轮廓，轮廓与组件保持 2 px 间距。
- 动画关闭后，所有状态仍能通过静态变化理解。
- 学习正文支持 200% 浏览器缩放，不出现水平页面滚动。

## 内容模型与 API 能力

### 建议数据结构

```ts
type CourseStep = {
  stableKey: string;
  lessonKey: string;
  position: number;
  type:
    | "scenario"
    | "misconception"
    | "yishan_method"
    | "principle"
    | "model"
    | "example"
    | "practice"
    | "analysis"
    | "summary";
  title: string;
  body: ContentBlock[];
  sourceRefs: SourceRef[];
  assessmentSkillRefs: string[];
  completionRule: CompletionRule;
};

type PracticeDefinition = {
  stableKey: string;
  schemaVersion: number;
  type: "single" | "multiple" | "sort" | "match" | "classify" | "data";
  prompt: ContentBlock[];
  options: PracticeOption[];
  attemptPolicy: "correct_to_continue";
  feedbackByOption: Record<string, FeedbackBlock>;
  remediationRefs: string[];
};

type LessonArtifactDefinition = {
  stableKey: string;
  schemaVersion: number;
  fields: ArtifactField[];
  requiredForCompletion: string[];
  sourceStepKeys: string[];
};
```

课程版本包含校验形态、内容哈希、公司内容哈希、工作流哈希、题库能力蓝图版本和来源复核日期。公司页或工作流发布新版本后，受影响课程进入 `REVIEW_REQUIRED`，员工可以继续已开始且仍安全的内容，新的课程版本暂停发布。

首期以完整 `CourseVersion` 作为唯一发布和回退单位。章节、小节、步骤、练习和成果物使用跨版本稳定键，子对象中的 `schemaVersion` 只服务结构校验，不形成独立发布版本。学习注册固定开始时使用的课程版本，历史结果按该版本读取；新版本需要补学时，通过稳定键生成差异和补学步骤。

### API 边界

| 能力           | 建议接口                                                              | 权限与约束                                    |
| -------------- | --------------------------------------------------------------------- | --------------------------------------------- |
| 课程目录与资格 | `GET /api/v1/courses`                                                 | 登录员工读取自己的进度与入口状态              |
| 课程介绍       | `GET /api/v1/courses/:slug`                                           | 返回可见目录、版本、校验形态和开始位置        |
| 创建注册       | `POST /api/v1/courses/:slug/enrollments`                              | 幂等创建，并固定当前课程版本                  |
| 学习工作台     | `GET /api/v1/course-enrollments/:id/lessons/:lessonKey`               | 只返回注册版本中已解锁内容和可见来源摘要      |
| 步骤完成       | `PUT /api/v1/course-enrollments/:id/steps/:stepKey`                   | 幂等写入，携带客户端操作 ID                   |
| 练习提交       | `POST /api/v1/course-enrollments/:id/exercises/:exerciseKey/attempts` | 服务端判定，首次选择与最终选择分开保存        |
| 成果物保存     | `PUT /api/v1/course-enrollments/:id/artifacts/:artifactKey`           | Zod 校验、版本冲突检测、字段级长度限制        |
| 补学队列       | `GET /api/v1/courses/:slug/remediation`                               | 只接收测评服务返回的清洗后能力和补学代码      |
| 结业与评价     | `POST /api/v1/course-enrollments/:id/complete`                        | 完成规则、证书签发和返回资格摘要              |
| 课程反馈       | `PUT /api/v1/course-enrollments/:id/feedback`                         | 可跳过，每个注册保存一份可更新反馈            |
| 证书           | `GET /api/v1/course-enrollments/:id/certificate`                      | 本人读取最新有效证书和历史状态                |
| 内容管理       | `/api/v1/admin/courses/*`                                             | `EDITOR` 复核，`ADMIN` 发布、退役和看个人数据 |

所有写接口沿用现有 Session、CSRF 和审计能力。服务端忽略客户端提交的正确状态、解锁状态和分数，统一根据已发布内容版本重新计算。

### 学习记录

服务端记录：

- 当前课程、章节、小节和步骤。
- 步骤开始时间、有效学习时间和完成时间。
- 模型节点打开记录。
- 练习首次选择、最终选择、尝试次数和误区标签。
- 章节挑战、成果物和结业项目状态。
- 课程版本和来源版本。

学习记录和正式测评记录分表保存，通过用户、稳定能力代码和版本建立关联。课程服务不直接解析测评报告中的题目、答案或选项；测评模块先校验报告所有权，再返回只含误区代码、能力代码和补学代码的 DTO。

学习分析不记录自由文本逐键输入、鼠标轨迹或客户材料原文。成果物正文按内部培训资料管理；埋点只保存步骤、状态、次数、耗时区间和误区代码。保留期限、导出权限和员工查看范围沿用公司现有数据治理规则，并在上线前由管理员确认。

## 内容管理后台

课程后台需要提供 6 个工作区：

| 工作区 | 能力                                        |
| ------ | ------------------------------------------- |
| 大纲   | 拖动章节、小节和步骤，检查编号与解锁关系    |
| 内容   | 编辑情境、方法、原理、案例和小结            |
| 模型   | 选择模型类型，编辑节点，预览桌面和手机布局  |
| 练习   | 配置选项、提示、逐项解析、误区和通过规则    |
| 来源   | 绑定公司内容、工作流、论文、数据或 SOP 版本 |
| 发布   | 运行结构、来源、可访问性和敏感信息门禁      |

课程发布至少需要课程负责人、业务负责人和题目复核人确认，三个复核角色使用不同账号。涉及正式题库能力映射时，后台只显示能力标签和受控题号引用，不显示正式答案。

内容版本依次经过 `DRAFT`、`BUSINESS_REVIEW`、`QUESTION_REVIEW`、`READY`、`PUBLISHED` 和 `RETIRED`。同一版本不能跳过两个复核阶段直接发布；紧急下架可以从任一已发布状态进入 `RETIRED`，并记录操作者和原因。

后台在版本标题旁持续显示 `PILOT` 或 `RELEASE`。`PILOT` 的发布操作只能切换到小范围试学，缺少 20 节完整性、第五章综合实战或百脉达处理结论时，界面不提供“全员发布”。`RELEASE` 需要完整结构门禁、三项人工复核、代表性员工试学以及百脉达的“已纳入”或“经业务负责人确认不适用”记录。

### 课程助手

首期保留参考图右侧的浮动助手位置和视觉形态。点击后打开来源受控的帮助面板，提供术语解释、当前步骤来源、回看模型和反馈入口。首期不开放自由对话，也不自动生成课程结论。后续开放问答时，回答需要显示来源、课程版本和反馈入口，并进入回答审计。

## 状态与异常页面

需要设计以下状态：

- 首次进入和继续上次进度。
- 内容加载、模型加载和练习保存。
- 网络中断，继续显示当前内存中的步骤并提示稍后同步；默认不把客户材料、成果物或正式测评信息写入持久离线缓存。
- 保存冲突，使用服务端最新版本并保留本地草稿供比较。
- 来源复核中，历史内容可读，新学习暂停。
- 试学版，持续显示试学标签、授权范围和无证书说明。
- 课程版本升级，显示变更摘要和需要补学的小节。
- 权限不足、课程不存在和步骤地址失效。
- 课程完成、章节完成和全部补学完成。

重新登录、浏览器历史恢复和 `pageshow` 触发时重新验证课程权限。任一课程 API 返回 401 后，沿用 Orosaga 的文档级跳转规则回到登录页，恢复登录后再返回原步骤。

404 页面延续 Orosaga 的山路语言，同时提供返回课程中心和继续当前课程两个入口。

## 埋点与学习分析

学习分析只服务课程质量和个人补学，不做公开排名。核心事件包括：

- `course_started`
- `lesson_started`
- `step_completed`
- `model_node_opened`
- `practice_answered`
- `practice_retried`
- `lesson_artifact_saved`
- `chapter_completed`
- `course_completed`
- `remediation_opened`
- `course_feedback_submitted`
- `certificate_viewed`
- `certificate_printed`

课程负责人重点看完成率、每步退出率、首次正确率、重答后正确率、误区分布、模型互动率和补学回流率。样本少于 30 时不输出稳定性判断。

## UI 交付切片

UI 的实施边界以《Orosaga 在线课程系统升级执行计划》为准，下面只说明每个纵向阶段需要交付的界面状态。

### 第一阶段：第 2 节纵向切片

完成首页入口、学习中心、课程介绍、双栏工作台、步骤导航、自动保存、基础内容组件和第 2 节单选练习，界面明确显示 `PILOT`。

### 第二阶段：四节样板和视觉校准

完成第 2、10、13、19 节，覆盖流程、数据、交付和风险场景，并完成 6 个参考状态、平板和手机的截图校准。

### 第三阶段：完整 20 节

补齐 20 节、前 4 章挑战和第 20 节综合实战，完成 20 套唯一 HTML 结构模型、移动端有序降级、打印结构和等价文字说明。

### 第四阶段：结业闭环

完成确定性评价、课程反馈、证书、正式测评资格和清洗后的补学入口。

### 第五阶段：内容后台和全员发布

上线课程编辑、来源复核、`PILOT` 与 `RELEASE` 校验、预览、发布、退役、分析和回退界面。

## 验收标准

### 视觉与交互

- 6 个固定参考场景均完成同尺寸截图叠加校准，关键几何量满足“视觉校准方法”的偏差要求。
- 1920 px、1440 px 和 1280 px 下的栏宽、正文宽度、底栏位置保持同一比例逻辑。
- 当前步骤、完成状态、锁定状态和需复习状态在 3 秒内可辨认。
- 练习答对、答错、重答和查看解析全过程没有布局跳动。
- 20 节课程分别绑定唯一 HTML 结构模型，结构类型、节点数量和读图提示通过内容校验。
- 375 px 和 320 px 下无文字截断、按钮重叠和页面级横向滚动。
- `PILOT` 标签、授权范围和无证书说明在课程中心、介绍页和结业摘要中保持一致。
- 结业页能区分课程评价、正式测评状态和证书状态，A4 横向打印无导航、截断和溢出。

### 功能

- 页面刷新、重新登录和跨设备后可以恢复到最后一步。
- 必做练习完成正确判断前无法进入下一步，首次错误时立即显示定向提示和完整解析。
- 课程版本升级不会覆盖历史学习记录。
- 第 20 节只计一次，同时完成综合实战和第五章挑战。
- `PILOT` 版本不能切换到全员可见，也不能签发证书或开放正式测评。
- 正式测评答案不会进入课程 API、前端包、日志或公开仓库。
- 公司内容、工作流或题库能力蓝图变化会触发来源复核。
- 客户材料、成果物和正式测评信息不会进入持久离线缓存。

### 可访问性与性能

- 课程主路径通过键盘和屏幕阅读器完成。
- 所有正文和状态颜色满足 WCAG 2.2 AA 对比度。
- 首屏核心内容没有明显布局跳动，交互模型按需加载。
- 在统一测试设备和内部网络条件下，普通内容步骤的 p75 可交互时间不超过 1.5 秒；测试设备、网络和样本量写入验收记录。
- 模型加载失败时显示完整文字版，完成状态和下一步不受影响。

## 已给出默认值的产品决策

1. 系统入口固定为“学习中心”，课程短名为“GEO 实战训练营”，正式课程名为“从 AI 回答到 GEO 交付”。
2. 正式测评首期采用强解锁，只有完整 `RELEASE` 课程结业可以开放；已有有效测评记录和管理员豁免继续有效。
3. 前 4 章各有独立挑战，第 20 节综合实战兼作第五章挑战，均允许不限次数补练并保留首次结果。
4. 每节首发配置 1 道必做练习，可选迁移练习进入增强内容且不参与完成判断。
5. 移动端首期支持查看、选择和轻量字段编辑，复杂成果物在桌面端完成。
6. 课程蓝按参考图保留，作为学习路径和模型交互色；Orosaga 深山绿继续承担完成和可信状态。
7. 浮动助手按参考图保留，首期打开来源受控的帮助面板，自由对话等待回答审计能力上线。

这些默认值可以在方案确认时调整。开发排期、内容数据结构和验收用例都按当前默认值编制。
