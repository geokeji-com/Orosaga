# Orosaga 在线课程用户旅程测试报告

> 测试日期：2026-08-03
> 测试对象：Orosaga 正式站与当前工作区版本
> 正式站：<https://orosaga.wanhuchangan.com>
> 工作区版本：`codex/geo-online-course-system` PR 前最终验证版本
> 报告性质：一次发布现状快照，后续发布后需要重新执行完整课程测试

## 测试结论

本轮测试结论为 **阻断**。正式站没有可用的在线课程入口、课程页面和课程接口，学员无法开始第 1 节，20 节课程、练习反馈、进度恢复、综合实战、课程评价和证书均无法进入测试。

正式站本身在线，首页和健康检查可以访问。课程入口 `/courses` 返回 HTTP 404，课程接口 `/api/v1/courses` 也返回 HTTP 404。当前工作区只有课程方案文档，尚未包含课程协议、数据库模型、服务端模块、Web 页面和课程端到端测试。现状与“课程系统已经上线”的预期不一致。

## 测试方法与边界

本轮按一名首次访问的内部学员设计路径：打开正式站、查看登录入口、进入学习中心、打开课程介绍、开始第 1 节，再依次完成 20 节。入口阻断出现后，测试继续核对正式站页面路由、课程 API、线上前端构建清单、当前仓库实现和自动化测试清单。

测试浏览器没有员工飞书会话。登录页和 OAuth 启动接口可达，OAuth 接口会跳转到飞书授权页。课程页面与课程接口均不存在，这项结果不依赖员工身份：同一正式站的 `/api/v1/me` 会对匿名请求返回 401，`/api/v1/courses` 返回 404，说明课程接口没有注册。

本轮没有提交课程答案、评价或证书申请，也没有修改线上或本地业务数据。

### 当前工作区

当前工作区的事实与线上表现一致：

- `apps/web/src/router.tsx:65-137` 注册首页、知识页面和测评页面，没有课程中心、课程介绍、课程工作台、结业和证书路由。
- `apps/api/src/app.module.ts:12-21` 注册 `AssessmentModule` 等现有模块，没有 `CourseModule`。
- `apps/api/prisma/schema.prisma:9-88` 的用户关系包含测评记录，没有课程注册、课程进度、评价或证书关系。
- `apps/web/nginx.conf:45-48` 的已知 SPA 路由白名单没有 `/courses` 及其子路由。
- 自动化测试清单共有 53 个用例，覆盖门户、鉴权、测评和视觉基线。课程用例数为 0。

课程执行计划也把这些能力列在待开发清单中：`docs/ONLINE-COURSE-UPGRADE-EXECUTION-PLAN.md:734-791`。开工条件仍写为“收到计划确认并补齐开工前负责人后，从阶段 1 开始实施”，见同一文件 `1143-1145` 行。

## 问题分级

### CRS-001：正式环境没有课程系统

- 级别：P0
- 触发条件：学员访问学习中心、课程介绍或课程目录 API。
- 实际结果：页面与接口返回 404，学习流程在第 1 节之前终止。
- 影响：所有学员、全部 20 节内容、练习、进度、评价和证书。
- 现有保护为何没有拦截：健康检查只验证服务可用，发布包和 Nginx 验收没有课程路由与课程 API 的门禁。
- 修复建议：先完成课程纵向切片，实现协议、数据模型、API、Web 页面和课程包导入；发布为限定员工可见的 `PILOT`；通过入口与第 2 节试学验收后，再补齐 20 节并开放 `RELEASE`。

### CRS-002：Web 服务没有放行课程深链接

- 级别：P1
- 触发条件：浏览器直接打开 `/courses`、课程小节、章节总结、综合实战、结业或证书地址。
- 实际结果：`apps/web/nginx.conf:45-48` 只允许现有门户和测评路由。
- 影响：即使前端页面已经加入构建，刷新课程深链接仍会返回 404。
- 修复建议：把执行计划中确定的员工端与管理端课程路由加入精确白名单，继续保留额外层级 404；同步扩展 `scripts/check-nginx-routes.mjs` 的 200 / 404 路由矩阵。

### CRS-003：课程发布缺少自动化验收

- 级别：P1
- 触发条件：课程变更进入构建、发布或回归阶段。
- 实际结果：端到端测试清单没有 `course.spec.ts`，答错重试、进度恢复、强解锁、评价和证书没有自动检查。
- 影响：课程实现完成后仍可能带着主流程问题进入正式环境。
- 修复建议：增加课程接口集成测试和 Web 端到端测试。至少覆盖首次开始、连续完成、答错后纠正、跨刷新恢复、章节挑战、综合实战、评价可跳过、证书资格、移动端和键盘操作。

### CRS-004：运行状态无法映射到发布版本

- 级别：P2
- 触发条件：测试人员需要确认正式站运行的提交、课程版本或构建时间。
- 实际结果：`apps/api/src/common/health.controller.ts:9-13` 只返回 `status: ok`，无法从正式站确认部署提交。
- 影响：线上问题难以快速对应源代码，发布回归的证据链不完整。
- 修复建议：增加只含非敏感信息的 `/version` 或构建元数据，如提交短哈希、构建时间和应用版本。课程内容版本继续通过登录后的课程接口返回。

## 建议修复顺序

1. 明确本次课程发布使用的分支、提交、环境和试学员工范围。
2. 按执行计划完成阶段 1，交付课程协议、数据库、API、学习中心、课程介绍、学习工作台和一个完整小节。
3. 补齐课程路由白名单、API 鉴权、课程包导入和 `PILOT` 发布门禁。
4. 加入课程端到端测试与截图基线，在持续集成中阻止缺少课程路由的发布包上线。
5. 使用全新的员工测试账号完成第 1 至 20 节，覆盖一次答错纠正、一次刷新恢复、全部章节挑战、综合实战、评价和证书。
6. 完成桌面、平板、手机、键盘和无障碍回归，再决定是否开放给全员。
