## 执行结论

Orosaga 将增加一个登录内的“学习中心”，首门课程使用短名称“GEO 实战训练营”，正式课程名为“从 AI 回答到 GEO 交付”。员工使用飞书登录后仍进入 Orosaga 首页，可以从顶部导航的“学习中心”进入课程中心，也可以在首页“新手村”按入职路线开始课程。

课程放在“读懂业务地图”之后、“完成第一次同行”之前。现有 GEO 基础能力测评保留独立入口，并调整为课程结业后开放。上线前已经参加过测评的员工自动保留资格，管理员可以为专项补学或特殊安排添加豁免。

首期课程共 5 章、20 节。前 4 章各有一个独立章末挑战，第 20 节综合实战兼作第五章挑战和结业项目，课程只记录一次。每节课沿用已经确认的学习顺序：训练情境、首次判断、错误路线、移山做法、底层原理、模型演示、业务应用、练习、完整解析、成果物。普通小节预计 12 至 18 分钟，第 20 节预计 30 分钟，必修总时长约 6 至 7 小时。

技术实现完全沿用当前 npm workspaces 单体仓库：React 19、TypeScript、Vite 8、React Router 7、TanStack Query、NestJS 11、Zod、Prisma 7.9 和 PostgreSQL 16。登录继续使用飞书 OAuth、服务端 Session 和 CSRF。部署继续使用当前 Docker Compose、Nginx、RDS 和私有 OSS，不增加新的运行服务。

完整升级会涉及 Web、API、共享协议、数据库、内容导入、测试、运维和文档，预计新增或修改 40 至 55 个文件。实施按可独立验收的纵向阶段推进，每一阶段都保留可运行、可回退的产品状态。

## 目标与范围

### 本次升级要完成的用户结果

- 员工登录后能在 10 秒内找到学习入口，看到自己的课程状态和下一步。
- 员工能跨刷新、重新登录和设备恢复到最近学习步骤。
- 课程能用网页模型、训练材料、练习和成果物讲清 GEO 业务方法。
- 练习答对、答错都显示完整解析；答错后完成纠正确认才能继续。
- 20 节学习逐步形成一份 90 天 GEO 作战包。
- 课程完成后展示确定性学习评价、正式测评入口和结业证书。
- 正式测评报告能按误区标签把员工带回具体课程小节。
- 课程负责人能管理版本、来源、复核、发布、下架和学习质量。

### 本期纳入

- 学习中心、课程介绍、双栏学习工作台、章节总结、综合实战、结业页和证书页。
- 首页学习入口、个性化招呼语、继续学习状态和课程完成状态。
- 5 章 20 节课程、每节必做练习和训练成果物。
- 流程链、闭环、二维矩阵、时间线和决策树 5 类首发交互模型。
- 分层图和因果图的可访问静态网页版本。
- 前 4 个章末挑战、第 20 节综合实战、确定性评分和正式测评强解锁。
- 课程版本、进度、练习、成果物、评价、证书和来源复核数据。
- 私有课程包导入、自动门禁、人工复核、发布、退役和审计。
- 桌面、平板、手机、键盘、屏幕阅读器和 A4 证书打印适配。
- 单元、集成、端到端、视觉、无障碍、安全和生产路由验收。

### 本期不纳入

- 面向外部客户或公众开放的课程注册和证书验证。
- 视频直播、录播托管、班级群、讲师排课和付费能力。
- 运行时大模型自由评分、自由对话式课程助手和自动生成课程事实。
- 部门排行榜、公开排名、绩效联动和淘汰用途。
- 真实客户材料、员工个人材料和正式测评答案进入前端构建包。
- 复杂富文本协同编辑和多人实时共同编辑。
- 对课程内容做持久离线缓存。

### 两份 V2.1 方案的实施裁决

两份方案已经完成内容和交互复核。本执行计划补齐了研发阶段必须唯一确定的落点：

- 全部课程接口统一使用现有 `/api/v1` 前缀。
- 首期每节配置 1 道必做练习；可选迁移练习进入内容增强，不影响结业。
- 首发交互模型固定为流程链、闭环、二维矩阵、时间线和决策树。分层图和因果图先使用可访问的静态网页版本。
- 课程使用当前发布版本指针，进行中的注册固定原版本，内容回退切换指针。
- 课程版本分成 `PILOT` 和 `RELEASE` 两种校验形态，试学子集不能全员发布、签发证书或开放正式测评。
- 第 20 节综合实战兼作第五章挑战，不再创建重复挑战记录。
- 课程证书按课程结业签发，正式测评通过状态独立展示。
- 前三个开发阶段通过受控课程包导入内容，阶段 5 再提供完整内容管理界面。
- 首期继续使用 `EMPLOYEE`、`EDITOR`、`ADMIN` 三个角色，不新增全局角色。
- 测评强解锁上线时，已有有效测评记录的员工自动保留资格。
- 课程与测评通过稳定能力代码关联，测评模块只向课程模块返回清洗后的补学 DTO。

## 完整用户旅程

```text
飞书 OAuth
  -> AuthGate 验证登录与在职状态
  -> Orosaga 首页
      -> 顶部“学习中心”
      -> 新手村“GEO 实战训练营”
          -> 课程中心
              -> 课程介绍与开始位置
                  -> 5 章、20 节学习工作台
                      -> 每节练习与成果物
                      -> 前 4 章章末挑战
                  -> 第 20 节综合实战，兼作第五章挑战
              -> 结业评价
                  -> 结业证书
                  -> GEO 基础能力测评
                      -> 诊断报告
                          -> 课程补学队列
```

### 首次学习

1. 员工从首页进入课程介绍页。
2. 系统展示 5 章、20 节、预计用时、解锁规则和成果物说明。
3. 点击“开始第 1 节”后，服务端幂等创建课程注册记录，并固定当前课程版本。
4. 学习工作台打开第 1 节第 1 步，左侧展示完整大纲，右侧只呈现当前学习任务。
5. 阅读步骤可以直接继续，模型步骤完成关键节点或文字版确认后继续。
6. 必做练习完成正确判断，成果物满足最小字段后，本节完成。

### 回访继续

1. 首页、课程中心和课程介绍页都读取同一个服务端进度。
2. “继续学习”进入 `currentStepKey`，不固定跳回第 1 步。
3. 页面刷新和重新登录后继续使用服务端记录。
4. 多设备同时修改成果物时使用乐观锁，后提交设备看到冲突比较条。

### 答错后的学习

1. 员工提交答案，服务端按已发布练习键判断。
2. 接口返回结果、定向提示、完整解析、误区编码和补学引用。
3. 页面立即显示错误状态和完整解析，反馈阶段锁定选项。
4. 员工读完解析后点击“我再想一次，重新选择”，再完成纠正确认。连续两次答错时先回看关联模型。
5. 服务端保留首次选择、最终选择、尝试次数和误区，纠正完成后解锁下一步。

### 章节挑战与综合实战

1. 前 4 章各自完成 4 节后开放章末挑战。
2. 前 4 个章末挑战达到 80%，且治理关键题通过后开放下一章。
3. 第 17 至 19 节及前 4 个章末挑战通过后，开放第 20 节综合实战。
4. 综合实战总分达到 80，五个维度各达到本维度满分的 60%，治理关键项通过，第 20 节、第五章和课程同时完成。
5. `RELEASE` 注册在同一事务中写入结业状态和证书记录。正式测评接口随后按结业记录、历史保留资格或管理员豁免实时计算资格。
6. `PILOT` 注册只生成试学完成摘要和反馈，不写入结业、证书或正式测评资格。

## 技术架构

### 架构选择

课程使用“服务端版本化内容、私有内容包导入、前端类型化渲染、服务端判定进度”的方案。课程引擎、内容和学习记录都进入现有 API 与 PostgreSQL，前端只负责渲染和提交用户动作。

最小替代方案是把 20 节 Markdown 直接打进前端，并用浏览器保存进度。该方案无法满足私有内容隔离、跨设备进度、服务端解锁、练习答案隔离、来源复核、证书和管理审计，因此不采用。

### 组件关系

```text
Feishu OAuth / Session
          |
          v
React Router + AuthGate
          |
          +--> HomePage 课程摘要
          +--> Course pages + TanStack Query
          +--> Assessment report 补学入口
                         |
                         v
                 /api/v1 CourseModule
                    |        |        |
                    |        |        +--> AuditLog
                    |        +----------> AssessmentRemediationService
                    +-------------------> Prisma / PostgreSQL
                                              |
                                              +--> 私有课程包导入
                                              +--> 版本、进度、练习、证书
```

`CourseModule` 单向依赖 `AssessmentModule` 导出的 `AssessmentRemediationService`。该服务先校验当前用户拥有指定测评报告，再返回 `assessmentAttemptId`、`blueprintVersion`、`misconceptionCodes`、`skillCodes` 和 `remediationCodes`，不返回题干、选项、答案或评分密钥。`AssessmentService` 直接通过 Prisma 查询课程结业记录和豁免记录，不导入 `CourseModule`，避免形成 Nest 模块循环依赖。

### 内容边界

- 完整课程包从仓库外的受控目录只读导入。
- 公开仓库只保存 schema、引擎、虚构最小测试夹具和不含业务答案的测试数据。
- Web Bundle 不含 20 节正文、练习键、正式题目、员工资料、真实客户材料或内部地址。
- 员工登录后，课程 API 只返回当前注册版本中已发布且已解锁的内容。
- 课程练习的公开题面和服务端答案键分表保存。
- 正式 50 题继续使用现有测评私有包和测评表，课程服务不能读取正式答案键。
- `CourseStep.skillRefs` 只保存 `DATA_BOUNDARY`、`CAUSAL_OVERREACH` 等稳定能力代码。维度名称、正式题号和能力代码的关系由带版本的测评蓝图维护。

`Course.visibility` 使用 `HIDDEN`、`PILOT` 和 `ALL_EMPLOYEES`。`HIDDEN` 只允许编辑者和管理员预览；`PILOT` 只允许被授权员工学习；`ALL_EMPLOYEES` 对所有在职员工开放。

### 学习记录

| 模型                        | 关键字段                                                                                   | 作用                     |
| --------------------------- | ------------------------------------------------------------------------------------------ | ------------------------ |
| `CourseAccessGrant`         | `courseId`、`userId`、`grantType`、`actorId`                                               | 生产内小范围试学授权     |
| `CourseEnrollment`          | `userId`、`courseVersionId`、`status`、`currentStepId`、`startedAt`、`completedAt`         | 固定版本的个人课程记录   |
| `CourseStepProgress`        | `enrollmentId`、`stepId`、`status`、`activityMs`、`completedAt`、`state`                   | 步骤进度和等价完成状态   |
| `CourseExerciseAttempt`     | `enrollmentId`、`exerciseId`、`attemptNo`、`response`、`correct`、`misconceptionCode`      | 首次选择、纠正和章节成绩 |
| `CourseArtifactSubmission`  | `enrollmentId`、`definitionId`、`payload`、`revision`、`completedAt`                       | 训练成果物和乐观锁       |
| `CourseEligibilityOverride` | `userId`、`courseId`、`type`、`reason`、`actorId`、`expiresAt`                             | 正式测评豁免和特殊安排   |
| `CourseCertificate`         | `certificateNo`、`recipientName`、`scoreSnapshot`、`status`、`issuedAt`                    | 不可变结业证明           |
| `CourseFeedback`            | `usefulness`、`clarity`、`difficulty`、`recommendation`、`mostHelpfulLessonKey`、`comment` | 结业或试学后的课程评价   |

`CourseVersion.packProfile` 使用 `PILOT` 和 `RELEASE`。`PILOT` 可以包含指定样板小节，且 `Course.visibility` 只能是 `HIDDEN` 或 `PILOT`；`RELEASE` 通过完整门禁后才能切换为 `ALL_EMPLOYEES`。数据库约束和服务端发布规则共同阻止试学版本签发证书、开放正式测评或成为全员当前版本。

首期以完整 `CourseVersion` 作为唯一发布、固定和回退单位。章节、小节、步骤、练习与成果物使用跨版本稳定键，子对象里的 schema 版本只服务 payload 校验，不形成独立可发布版本。

`CourseEnrollment` 固定到开始学习时的课程版本。发布新版本后，新注册员工使用新版本；进行中的员工继续旧版本；旧版本发生安全问题时可以单独退役并暂停访问。证书和历史评价继续保留版本快照。员工完成任一合格 `RELEASE` 版本后，后续常规内容更新不撤回既有测评资格；安全或评分完整性事件由管理员按范围复核。

### 数据约束

- 同一员工、课程版本只能有一个有效注册记录。
- 同一步骤的完成写入使用幂等操作 ID。
- 同一成果物使用 `revision` 做乐观锁，冲突返回 `409`。
- 服务端忽略客户端传入的正确性、分数、解锁和结业状态。
- 练习尝试只允许关联当前注册版本中的练习。
- 证书号唯一，格式为 `YS-GEO-{YYYY}-{8 位大写标识}`，冲突时重新生成。
- 证书中的姓名、课程名、课程版本、成绩和日期使用签发时快照。
- 已发布版本的结构化内容禁止原地修改，修订通过新版本完成。
- 同一注册最多保存一份课程反馈，重复提交更新现有记录并保留审计时间。
- 同一 `RELEASE` 注册只能有一张当前有效证书，历史撤销和重签记录继续可查。

### 正式测评接口调整

`AssessmentEligibility` 增加 `COURSE_REQUIRED` 状态和课程摘要。`overview` 与 `createAttempt` 使用同一套服务端资格规则：

- 已完成课程的员工可以开始测评。
- 上线前已经有非作废测评记录的员工自动保留资格。
- 管理员有效豁免可以开放资格。
- 已开始的测评继续完成，不受课程版本变化影响。
- 未满足条件时，测评介绍页显示课程完成度和“前往学习”按钮。
- 已完成合格 `RELEASE` 版本的资格在常规课程更新后继续有效。

课程补学接口不读取完整测评报告。`AssessmentRemediationService` 完成报告所有权校验和安全字段提取，`CourseService` 只把清洗后的稳定能力代码映射到课程稳定步骤键。

## 课程进度和评分规则

### 步骤完成

| 步骤类型               | 完成条件                                     |
| ---------------------- | -------------------------------------------- |
| 阅读、故事、误区、原理 | 页面成功打开即可继续，停留时间只用于分析     |
| 交互模型               | 完成声明的关键节点，或使用文字版确认等价内容 |
| 必做练习               | 完成正确判断，首次错误继续保留               |
| 训练成果物             | 必填字段通过 Zod 和长度校验并保存            |
| 小结                   | 练习和成果物均完成                           |

### 章节挑战

- 前 4 章各自完成 4 节后开放独立章末挑战。
- 可以不限次数练习，保存首次结果、最好结果和最近结果。
- 最好成绩达到 80% 后通过。
- 标记为治理关键的题必须通过，避免平均分掩盖高风险判断。
- 失败后提供本章具体小节和模型节点，不预测下次成绩。

### 综合实战

| 维度       | 分值 | 通过证据                               |
| ---------- | ---: | -------------------------------------- |
| 事实与知识 |   20 | 事实有来源，冲突和缺口有处理           |
| 方法与策略 |   20 | 问题、内容、信源和平台动作对应         |
| 数据与归因 |   20 | 指标可复算，采集可比较，结论保留边界   |
| 交付与运营 |   25 | 负责人、里程碑、验收和迭代动作完整     |
| 治理与沟通 |   15 | 无虚假、越权和过度承诺，异常有升级路径 |

第 20 节综合实战在第 17 至 19 节和前 4 个章末挑战通过后开放，同时承担第五章挑战和结业项目。首期使用结构化选择、排序和必填字段，由服务端固定规则评分。总分需要达到 80，每个维度需要达到本维度满分的 60%，治理关键项需要全部通过。开放文本用于记录思路，不进入自动评分。

### 自动门禁

`validate` 先运行两类课程包共有门禁：

- 包内小节键、步骤键、练习键和成果物键唯一。
- 包内每节步骤数为 8 至 12，并包含故事、误区、移山做法、原理、模型、练习、解析和成果物。
- 包内每节恰好有 1 道必做练习和 1 份成果物。
- 所有模型有替代文本和文字完成路径。
- 所有练习键、反馈、误区和补学路由完整。
- 所有来源有版本、哈希和复核日期。
- `BAIMAIDA-PENDING` 没有承载课程事实、答案或评分规则。
- 内容不含真实客户标识、员工资料、飞书节点 token、内部地址、任意脚本或未受控 HTML。

`PILOT` 额外检查授权小节非空且都存在于正式 20 节清单，只允许 `HIDDEN` 或 `PILOT` 可见性。阶段 1 的包只含第 2 节，阶段 2 的包包含第 2、10、13、19 节。试学包可以缺少其余章节、能力和 SOP 覆盖，不生成结业、证书或测评资格。

`RELEASE` 额外执行完整门禁：

- 章节数等于 5，小节数等于 20。
- 前 4 个独立章末挑战和第 20 节综合实战都存在。
- GEO-001 至 GEO-050 在主映射中连续、唯一、无缺失。
- D1 至 D5 各覆盖 10 个正式测评能力点。
- SOP 001 至 050 连续覆盖。
- 五类首发交互模型都有实际课程位置。
- 百脉达状态为“已纳入”或“已确认不适用”，并带业务负责人复核记录。
- 业务、题目隔离和代表性员工试学三项人工复核齐全且账号分离。

### 人工门禁

课程版本按以下状态流转：

```text
DRAFT
  -> BUSINESS_REVIEW
  -> QUESTION_REVIEW
  -> READY
  -> PUBLISHED
  -> RETIRED
```

1. 课程负责人完成草稿并运行自动门禁。
2. 业务负责人检查公司事实、移山流程、术语、成果物和客户沟通口径。
3. 题目复核人检查答案唯一性、干扰项合理性、误区标签和正式题库隔离。
4. 代表性员工完成第 2、10、13、19 节试学，记录时长、卡点和理解偏差。
5. 管理员核对三项复核记录、来源状态和内容哈希后发布。

作者、业务复核人和题目复核人使用不同账号。管理员发布可以由第四个账号完成。服务端拒绝同一账号同时完成两个复核门禁。复核引用保存飞书文档链接、评审单号或会议纪要编号。

### 百脉达处理

当前资料中没有找到可以确认身份和版本的“百脉达”正式文档。实施保留 `BAIMAIDA-PENDING` 来源键，并采用以下固定规则：

- 课程引擎和数据结构可以按计划开发。
- 内容可以使用已经确认的 `ORO-COMPANY`、`ORO-WORKFLOW`、`ASSESSMENT-BLUEPRINT`、`OPS-SOP-50`、`SERVICE-METHODOLOGY` 和 `GEO-EVIDENCE`。
- 任何引用 `BAIMAIDA-PENDING` 的课程事实、练习答案或评分规则都无法通过自动门禁。
- 正式资料确认后创建新的来源版本，重新执行受影响小节的业务复核。
- `PILOT` 可以在不引用该来源时继续试学。
- `RELEASE` 需要业务负责人把状态改为“已纳入”或“已确认不适用”，待确认状态不能全员发布。

### 来源变化触发矩阵

| 来源键                 | 触发位置                         | 处理方式                                               |
| ---------------------- | -------------------------------- | ------------------------------------------------------ |
| `ORO-COMPANY`          | 公司内容发布服务                 | 自动标记受影响课程版本 `REVIEW_REQUIRED`               |
| `ORO-WORKFLOW`         | 工作流管理发布服务               | 自动按稳定来源键定位受影响小节                         |
| `ASSESSMENT-BLUEPRINT` | 私有测评包导入和蓝图发布         | 比较蓝图版本与稳定能力代码映射，暂停新的课程发布       |
| `OPS-SOP-50`           | 受控课程包导入命令               | 导入时比较哈希，变化后要求业务复核                     |
| `SERVICE-METHODOLOGY`  | 受控课程包导入命令               | 导入时比较哈希，变化后要求业务复核                     |
| `GEO-EVIDENCE`         | 证据基线维护和受控课程包导入命令 | 到期或哈希变化后标记对应原理页复核                     |

前两类来源由现有服务自动触发。其余来源首期通过受控导入命令和管理后台复核动作触发，运行手册需要写清负责人、检查频率和失败处理。

## 分阶段执行

### 开工前确认，不计入交付阶段

确认产品名、入口、课程主线、强解锁、证书规则和复核负责人。本节只决定能否开始阶段 1，不作为开发阶段，也不计算工程交付物。

**输入**：本执行计划和两份 V2.1 方案。

**完成证据**：业务负责人回复确认默认决策，或逐项给出修改。

**回退**：当前产品没有变化。

### 阶段 1：可试学的纵向切片

**目标**：选定员工可以从首页进入课程，完成第 2 节并跨刷新恢复。

**范围**：

- 课程协议、核心数据表、受控导入和课程模块。
- `HIDDEN`、`PILOT`、`ALL_EMPLOYEES` 可见性。
- `PILOT` 与 `RELEASE` 两类课程包校验，阶段 1 只导入含第 2 节的 `PILOT` 包。
- 首页课程摘要、学习中心、课程介绍和双栏工作台。
- 第 2 节完整内容、流程链模型、单选练习、解析、纠正和成果物。
- 课程版本固定、步骤进度、练习尝试和成果物乐观锁。

**验收**：

- 未登录深链完成飞书登录后返回原步骤。
- 非试学员工在 `PILOT` 状态看不到课程正文。
- 试学员工完成答对和答错两条路径。
- 刷新、重新登录和跨设备恢复到最近步骤。
- 前端构建包扫描不到课程正文和练习键。
- 试学完成不产生结业、证书或正式测评资格。

**预计工作量**：工程 8 至 11 人日，内容与复核 3 至 5 人日。

### 阶段 2：四节 P0 样板和视觉复刻

**目标**：用第 2、10、13、19 节验证最复杂的内容和交互形态。

**范围**：

- 流程链、时间线和决策树三类交互模型。
- 数据判断、业务排程和风险治理练习。
- 左栏、大纲、底栏、帮助面板、平板抽屉和手机抽屉。
- 参考图对应的 6 个固定截图状态。
- 键盘、屏幕阅读器、文字降级和打印降级。
- 含第 2、10、13、19 节的 `PILOT` 包和持续可见的试学标识。

**验收**：

- 6 个参考状态完成同尺寸叠加校准。
- 左栏分隔线偏差不超过视口宽度 0.5%。
- 正文中心线偏差不超过 8 px，底栏基线偏差不超过 4 px。
- 320 px 下没有文字截断、按钮重叠和页面级横向滚动。
- 模型加载失败时文字版仍可完成步骤。
- `PILOT` 无法被切换为 `ALL_EMPLOYEES`。

**预计工作量**：工程 8 至 12 人日，内容与复核 8 至 12 人日。

### 阶段 3：完整 20 节和结业项目

**目标**：完整 5 章 20 节进入授权试学，前 4 个章末挑战和第 20 节综合实战可以完整验收。

**范围**：

- 补齐二维矩阵、闭环、分层 HTML 模型和因果文字链。
- 完成其余 16 节内容、练习、解析和成果物。
- 前 4 个独立章末挑战和兼作第五章挑战的第 20 节综合实战。
- 50 个能力点、50 个 SOP 问题域和来源路由门禁。
- 课程版本、来源复核和新旧注册版本隔离。
- 完整 `RELEASE` 门禁和从试学反馈生成的修订记录。
- 阶段 3 仍保持 `PILOT` 可见性，等待阶段 4 接通结业闭环后再进入全员发布审批。

**验收**：

- 私有课程包通过全部自动门禁。
- 20 节均能在目标时长内完成，普通小节试学中位时长为 12 至 18 分钟。
- 章节挑战、治理关键项和综合实战评分可以重复复算。
- 第 1 节到第 20 节完整主路径通过端到端测试。
- 完整课程结束时显示基础完成摘要，证书和正式测评仍由阶段 4 接通。
- 正式题目、答案和干扰项结构没有进入课程 API 或 Web Bundle。

**预计工作量**：工程 9 至 13 人日，内容与复核 24 至 36 人日。

### 阶段 4：评价、证书、正式测评和补学

**目标**：学习闭环覆盖结业评价、课程反馈、证书、正式测评和定向补学。

**范围**：

- 结业事务、五维评价和课程反馈。
- 证书签发、撤销、本人查看和 A4 打印。
- `COURSE_REQUIRED`、老员工自动保留和管理员豁免。
- 测评报告误区到课程小节和模型节点的补学映射。
- 课程中心统一展示课程、证书、测评和补学状态。
- `RELEASE` 结业与 `PILOT` 试学完成使用两套明确状态。

**验收**：

- 不满足课程条件时无法新建测评。
- 上线前已有有效测评记录的员工仍可继续测评。
- 结业事务重复提交只产生一张有效证书。
- 员工无法读取他人证书、成果物和反馈。
- 证书在 A4 横向打印中无导航、截断和溢出。
- 补学完成不会覆盖原始测评成绩。
- 常规课程版本更新不会撤销已完成 `RELEASE` 员工的测评资格。

**预计工作量**：工程 6 至 9 人日，内容与复核 3 至 5 人日。

### 阶段 5：内容后台和生产放量

**目标**：课程负责人可以在系统内完成复核、发布、质量检查和紧急下架。

**范围**：

- 大纲、内容、模型、练习、来源和发布 6 个管理工作区。
- 自动门禁、三项人工复核、内容哈希和当前版本切换。
- 聚合学习质量、课程反馈和样本量提示。
- 生产导入手册、课程路由矩阵、监控、数据保留和回退演练。
- `PILOT` 小范围放量后切换 `ALL_EMPLOYEES`。
- 只有通过完整门禁的 `RELEASE` 版本可以切换 `ALL_EMPLOYEES`。

**验收**：

- 作者、业务复核人、题目复核人和发布管理员形成完整审计链。
- 未完成复核或来源处于 `REVIEW_REQUIRED` 的版本无法发布。
- 当前版本可以切回仍有效的历史发布版本。
- 紧急下架停止新注册，保留历史记录和证书状态。
- 生产路由、匿名 401、登录回跳、备份、迁移和回退演练通过。

**预计工作量**：工程 8 至 11 人日，业务试学和发布复核 5 至 8 人日。

### 总工作量参考

在 1 名全栈工程师持续投入、产品与内容负责人并行配合的前提下，工程量约 39 至 56 人日，内容制作与人工复核约 43 至 66 人日。日历排期取决于内容负责人、业务负责人、题目复核人和代表性员工能否并行工作。每阶段完成后都可以独立评审和决定是否进入下一阶段。

## 发布、监控与回退

### 发布前

- 为 RDS 创建成功的手工物理备份并记录恢复锚点。
- 运行数据库内网、`sslmode=disable`、`orosaga` schema 和实际非 TLS 连接预检。
- 执行增量 Migration，检查所有新表和字段 SQL 注释。
- 从受控目录导入四节 `PILOT` 包，记录 SHA-256、来源版本和复核引用。
- 保持 `Course.visibility=HIDDEN` 完成生产预览，再切换到 `PILOT`，授权代表性员工完成第 2、10、13、19 节。
- 根据试学记录修订内容，导入完整 `RELEASE` 包并重新执行全量门禁和人工复核。
- 管理员确认当前版本的 `packProfile=RELEASE` 后切换到 `ALL_EMPLOYEES`。
- 最后启用正式测评强解锁，自动保留已经有测评记录的员工。

### 监控指标

- 课程概览和步骤接口成功率、p95 延迟。
- 注册创建、进度保存和成果物冲突率。
- 每节开始率、完成率和退出步骤。
- 必做练习首次正确率、纠正后正确率和重复误区。
- 章节挑战通过率和综合实战五维分布。
- 证书签发、重复请求、撤销和打印页错误。
- `COURSE_REQUIRED`、管理员豁免和正式测评转化。
- 课程来源复核到期和 `REVIEW_REQUIRED` 数量。
- 课程包导入、验证、复核、发布、回退和个人查看审计。

样本少于 30 时不输出稳定性或趋势结论。课程质量分析不用于个人绩效。

### 应用回退

1. 将 `Course.enabled` 设为 `false`，首页和课程中心停止新入口。
2. 保留课程表、注册、进度、成果物、证书和审计数据。
3. 把 `/opt/orosaga/current` 切回上一 release，继续使用现有应用回退流程。
4. 数据库新增表继续保留，不执行降级 SQL。
5. 修复后重新部署，恢复当前发布版本指针和课程入口。

### 内容回退

1. 管理员暂停新注册。
2. 将 `Course.currentVersionId` 切回仍有效的已发布版本。
3. 进行中的员工继续各自固定版本，涉及安全问题的版本单独退役。
4. 重新核对来源、内容哈希和复核记录。
5. 恢复新注册并记录回退原因。

### 证书异常

评分或内容错误影响结业时，先暂停新签发，定位受影响课程版本和注册记录。管理员按范围撤销证书并记录原因；修复版本发布后重新计算资格，满足条件的员工可以幂等签发新证书。历史审计继续保留。

## 数据保留与隐私

- 课程注册、结业摘要和证书默认保留 24 个月，最终期限由培训和安全负责人书面确认。
- 练习逐次答案、步骤活动和成果物正文默认保留 12 个月。
- 到期清理使用预览、目标摘要、数量上限和事务内重算，沿用测评保留命令的安全模式。
- 自由文本不记录逐键输入、鼠标轨迹或持久离线副本。
- 课程分析保存步骤、状态、次数、耗时区间和误区编码。
- 真实客户内容、内部地址、飞书节点 token 和员工资料不能进入课程包。
- 管理员查看个人成果物、反馈或证书需要审计。

## 依赖、假设与风险

### 已确认依赖

- Orosaga 当前飞书登录、Session、CSRF、角色和审计能力。
- 当前公司内容、工作流、50 题能力蓝图、运营 SOP 和服务方法论。
- 受控课程包目录和运维导入权限。
- 业务负责人、课程负责人、题目复核人和代表性员工试学。

### 实施假设

- 首期只服务移山科技在职员工。
- `displayName` 可以作为界面招呼语，证书使用签发时姓名快照。
- “澄屿工业热能”作为首期虚构客户，不使用真实客户素材。
- 正式测评继续保持培训掌握度用途。
- 课程证书代表内部课程结业，正式测评通过另行展示。
- 当前全局 CSS 和 Lucide 图标继续作为唯一界面实现方式。

### 主要风险与处理

| 风险                     | 影响                   | 处理                                                   |
| ------------------------ | ---------------------- | ------------------------------------------------------ |
| 百脉达资料未确认         | 部分业务口径无法引用   | 试学继续，`BAIMAIDA-PENDING` 阻断 `RELEASE` 全员发布   |
| 20 节内容制作慢于工程    | 完整放量延期           | 先交付 4 节 P0 样板，课程保持 `PILOT`                  |
| 试学包误作正式版本       | 缺课、错误发证或误解锁 | `packProfile` 双重门禁，`PILOT` 禁止全员发布和结业     |
| 强解锁影响已有员工       | 测评资格回退           | 按历史有效测评记录自动保留，管理员可豁免               |
| 课程版本更新影响在学员工 | 进度和内容错位         | 注册固定版本，新员工使用当前版本                       |
| 练习与正式题库过度相似   | 题库安全受损           | 独立题目复核、私有答案分表和相似结构人工检查           |
| 成果物包含敏感资料       | 数据泄露               | 训练场景和虚构数据，字段限制，私有 API，禁止离线持久化 |
| 双栏复刻在手机端失效     | 学习路径难用           | 手机单步骤、底部大纲抽屉和模型文字降级                 |
| 证书被理解为岗位认证     | 使用边界扩大           | 固定标注“内部培训结业证明”，与正式测评分开             |
| 管理后台范围过大         | 首发周期拉长           | 前三阶段使用受控导入，后台在阶段 5 完成                |

最脆弱的假设是内容负责人可以按阶段持续提供经过复核的课程包。若内容延迟，阶段 1 和阶段 2 仍能形成可试学的真实纵向切片，完整开放保持关闭。
